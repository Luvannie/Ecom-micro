1. Tổng quan

Project sử dụng Apache Kafka 3.7.0 vớiKRaft mode (không cần ZooKeeper) để implement event-driven architecture cho hệ thống micro services. Kafka đóng vai trò central message broker cho phép các services giao tiếp异步 qua event.

📦 Version

Apache Kafka 3.7.0

KRaft Mode (Không ZooKeeper)

🔧 Topology

Single Broker

Replication Factor: 1

🌐 Network

PLAINTEXT on port 9092

Advertised: localhost:9092

📊 Topics

7 Topics active

4 Services produce/consume

2. Infrastructure Configuration

Kafka được định nghĩa trong docker-compose.yml với cấu hình KRaft mode:

services:
  # ... other services ...

  kafka:
    image: apache/kafka:3.7.0
    ports:
      - "9092:9092"
    environment:
      # Node configuration
      KAFKA_NODE_ID: 1
      KAFKA_PROCESS_ROLES: broker,controller
      KAFKA_CONTROLLER_QUORUM_VOTERS: 1@kafka:9093

      # Listeners - internal and controller
      KAFKA_LISTENERS: PLAINTEXT://:9092,CONTROLLER://:9093
      KAFKA_ADVERTISED_LISTENERS: PLAINTEXT://localhost:9092
      KAFKA_LISTENER_SECURITY_PROTOCOL_MAP: CONTROLLER:PLAINTEXT,PLAINTEXT:PLAINTEXT
      KAFKA_CONTROLLER_LISTENER_NAMES: CONTROLLER
      KAFKA_INTER_BROKER_LISTENER_NAME: PLAINTEXT

      # Replication settings (dev mode)
      KAFKA_OFFSETS_TOPIC_REPLICATION_FACTOR: 1
      KAFKA_TRANSACTION_STATE_LOG_REPLICATION_FACTOR: 1
      KAFKA_TRANSACTION_STATE_LOG_MIN_ISR: 1
      KAFKA_GROUP_INITIAL_REBALANCE_DELAY_MS: 0
    volumes:
      - kafka-data:/tmp/kraft-combined-logs
⚠️ Lưu ý: Đây là cấu hình development (single broker, replication factor = 1). Cho production, cần nhiều brokers hơn và tăng replication factor.

4. Services và Kafka Components

4.1 Order Service

order-service Producer & Consumer Port 8086

Producers

OrderEventProducer - Gửi các events liên quan đến order:

  • publishReservationRequested() - Gửi yêu cầu reserve inventory
  • publishOrderConfirmed() - Thông báo order confirm (sau payment thành công)
  • publishOrderCancelled() - Thông báo order bị hủy
@Component
public class OrderEventProducer {
    private final KafkaTemplate<Object, Object> kafkaTemplate;

    public void publishReservationRequested(OrderResponse order) {
        var event = new ReservationRequestEvent(
            order.id(),
            order.items().stream()
                .map(item -> new ReservationItemEvent(
                    item.productId(), item.quantity()))
                .toList()
        );
        // Send với key = orderId để đảm bảo partition affinity
        kafkaTemplate.send(OrderTopics.INVENTORY_RESERVATION_REQUESTED,
                          order.id().toString(), event)
                     .get(5, TimeUnit.SECONDS);
    }

    // Record classes cho events
    public record ReservationRequestEvent(UUID orderId, List<ReservationItemEvent> items) {}
    public record ReservationItemEvent(UUID productId, int quantity) {}
    public record OrderCancelledEvent(UUID orderId, UUID userId, UUID reservationId) {}
    public record OrderConfirmedEvent(UUID orderId, UUID userId, BigDecimal total) {}
}

Consumers

PaymentEventConsumer - Nhận payment events từ Payment Service:

@Component
public class PaymentEventConsumer {

    @KafkaListener(topics = OrderTopics.PAYMENT_SUCCEEDED,
                     groupId = "${spring.application.name}")
    public void handleSucceeded(PaymentEvent event) {
        // Confirm order và gửi order.confirmed event
        eventProducer.publishOrderConfirmed(
            orderService.markConfirmed(event.orderId()));
    }

    @KafkaListener(topics = OrderTopics.PAYMENT_FAILED,
                     groupId = "${spring.application.name}")
    public void handleFailed(PaymentEvent event) {
        // Cancel order và gửi order.cancelled event
        eventProducer.publishOrderCancelled(
            orderService.cancelAfterPaymentFailure(event.orderId()));
    }

    public record PaymentEvent(UUID paymentId, UUID orderId, UUID userId,
                                     BigDecimal amount, String currency, String status) {}
}

InventoryEventConsumer - Nhận inventory reservation results:

@Component
public class InventoryEventConsumer {

    @KafkaListener(topics = OrderTopics.INVENTORY_RESERVED,
                     groupId = "${spring.application.name}")
    public void handleReserved(ReservationResult event) {
        orderService.markReserved(event.orderId(), event.reservationId());
    }

    @KafkaListener(topics = OrderTopics.INVENTORY_RESERVATION_FAILED,
                     groupId = "${spring.application.name}")
    public void handleReservationFailed(ReservationResult event) {
        orderService.markReservationFailed(event.orderId(), event.failureReason());
    }

    public record ReservationResult(UUID reservationId, UUID orderId,
                                      String status, String failureReason) {}
}

4.2 Inventory Service

inventory-service Consumer Producer Port 8085

Consumer

ReservationEventConsumer - Xử lý reservation requests từ Order Service:

@Component
public class ReservationEventConsumer {
    private final InventoryService inventoryService;
    private final InventoryEventProducer eventProducer;

    @KafkaListener(topics = InventoryTopics.RESERVATION_REQUESTED,
                     groupId = "${spring.application.name}")
    public void handleReservationRequested(ReservationRequest request) {
        var result = inventoryService.reserve(request);

        // Quyết định gửi success hay failure event
        if (result.status() == ReservationStatus.RESERVED) {
            eventProducer.publishReserved(result);
            return;
        }
        eventProducer.publishReservationFailed(result);
    }
}

Producer

InventoryEventProducer - Gửi kết quả reservation:

@Component
public class InventoryEventProducer {

    public void publishReserved(ReservationResult result) {

                     .get(5, TimeUnit.SECONDS);
    }

    public void publishReservationFailed(ReservationResult result) {
        kafkaTemplate.send(InventoryTopics.RESERVATION_FAILED,
                          result.orderId().toString(), result)

    }
}

4.3 Payment Service

payment-service Producer (Outbox) Port 8087

Payment Service sử dụng Transactional Outbox Pattern thay vì direct Kafka producer.

Outbox Pattern Flow

┌──────────────────────────────────────────────────────────────────┐ │ TRANSACTIONAL OUTBOX PATTERN │ └──────────────────────────────────────────────────────────────────┘ ┌─────────────────────┐ ┌─────────────────────┐ │ Payment Service │ │ Payment DB │ └─────────┬───────────┘ └─────────┬───────────┘ │ │ │ 1. Process payment │ │ ─────────────────────────► │ │ │ │ 2. Save Order + Outbox │ │ (SAME TRANSACTION) │ │ ─────────────────────────► │ │ │ │ 3. Commit │ │ ◄───────────────────────── │ │ │ │ ▼ │ ┌─────────────────────┐ │ │ OutboxEvent │ │ │ Table │ │ │ ─────────── │ │ │ • event_type │ │ │ • aggregate_id │ │ │ • payload │ │ │ • status (PENDING)│ │ └─────────┬───────────┘ │ │ │ │ 4. Polling │ │ ◄───────── │ ▼ │ ┌─────────────────────┐ │ │ OutboxPublisher │ │ │ (Scheduled Task) │ │ └─────────┬───────────┘ │ │ │ 5. KafkaTemplate.send() │ │ ─────────────────────────► │ │ │ │ 6. Mark as PUBLISHED │ │ ─────────────────────────► │ │ │ ▼ ▼ KAFKA (payment.succeeded hoặc payment.failed)

OutboxPublisher Implementation

@Component
public class OutboxPublisher {
    private final OutboxEventRepository repository;
    private final KafkaTemplate<Object, Object> kafkaTemplate;

    // Poll mỗi 5 giây cho đến khi có pending events
    @Scheduled(fixedDelayString = "${payment.outbox.publish-fixed-delay-ms:5000}")
    public void publishPending() {
        repository.findTop100ByStatusOrderByCreatedAtAsc(OutboxStatus.PENDING)
            .forEach(event -> {
                // Gửi bất đồng bộ đến Kafka
                CompletableFuture<SendResult<Object, Object>> future =
                    kafkaTemplate.send(event.getEventType(),
                                      event.getAggregateId().toString(),
                                      event.getPayload());

                future.whenComplete((result, ex) -> {
                    // Cập nhật trạng thái sau khi gửi
                    if (ex != null) {
                        event.markFailed();
                    } else {
                        event.markPublished();
                    }
                    repository.save(event);
                });
            });
    }
}
💡 Tại sao dùng Outbox Pattern?
  • Đảm bảo atomicity: Payment và Event được lưu trong cùng transaction
  • Tránh dual-writes: Không cần đồng thời gọi DB và Kafka
  • Đảm bảo at-least-once delivery: Event không bị mất nếu service crash

4.4 Notification Service

notification-service Consumer Port 8088

Notification Service nhận các events và gửi email/SMS notifications:

OrderEventConsumer

@Component
public class OrderEventConsumer {
    private final NotificationService notificationService;

    @KafkaListener(topics = "order.confirmed",
                     groupId = "${spring.application.name}")
    public void handleConfirmed(OrderConfirmedEvent event) {
        notificationService.sendEmail(
            event.userId(),
            recipient(event.userId()),
            "order-confirmed",
            Map.of("orderId", event.orderId(),
                   "total", event.total(),
                   "email", recipient(event.userId())));
    }

    @KafkaListener(topics = "order.cancelled",
                     groupId = "${spring.application.name}")
    public void handleCancelled(OrderCancelledEvent event) {
        // Gửi cả email và SMS
        notificationService.sendEmail(event.userId(), recipient(event.userId()),
            "order-cancelled", model);
        notificationService.sendSms(event.userId(), "+10000000000",
            "Order cancelled: " + event.orderId());
    }
}

5. Design Patterns

5.1 Consumer Group Pattern

Mỗi service sử dụng ${spring.application.name} làm group ID:

@KafkaListener(
    topics = "payment.succeeded",
    groupId = "${spring.application.name}"  // VD: "payment-service"
)
✓ Lợi ích:
  • Mỗi service là một consumer group riêng
  • Nhiều instances của cùng service cùng share messages (scale horizontally)
  • Khi order-service nhận message, notification-service cũng nhận được (fan-out)

5.2 Partition Affinity

Tất cả producers sử dụng orderId làm message key:

// Key = orderId.toString() đảm bảo tất cả messages của 1 order
// đi đến cùng một partition
kafkaTemplate.send(topic, order.id().toString(), event)
💡 Tại sao quan trọng? Kafka đảm bảo messages có cùng key luôn đi đến cùng partition. Điều này đảm bảo message ordering cho một đơn hàng cụ thể.

5.3 Outbox Pattern (Đã trình bày ở trên)

5.4 Fire-and-Forget với Acknowledgment

Producers sử dụng synchronous send với timeout để đảm bảo delivery:

try {
    kafkaTemplate.send(Topic, key, event)
                .get(5, TimeUnit.SECONDS);  // Timeout 5s, throw exception nếu fail
} catch (Exception e) {
    throw new RuntimeException("Failed to publish...", e);
}

7. Testing Strategy

7.1 Integration Tests

Các integration tests sử dụng @SpringBootTest với @ActiveProfiles("test"):

// Ví dụ: PaymentEventConsumerIT.java
@SpringBootTest
@ActiveProfiles("test")
class PaymentEventConsumerIT {
    @Autowired
    private PaymentEventConsumer consumer;

    @Autowired
    private OrderRepository orderRepository;

    @Test
    void paymentSuccessConfirmsOrderAndEmitsOrderConfirmed() {
        // Setup: Create pending order
        Order order = reservedOrder();
        orderRepository.save(order);

        // Act: Simulate payment success event
        consumer.handleSucceeded(new PaymentEvent(...));

        // Assert: Order status updated
        assertThat(orderRepository.findById(order.getId()))
            .get()
            .extracting("status")
            .isEqualTo(OrderStatus.CONFIRMED);

        // Verify: OrderConfirmed event published
        verify(eventProducer).publishOrderConfirmed(any());
    }
}

7.2 Unit Tests cho OutboxPublisher

// OutboxPublisherTest.java
@Test
void publisherSendsEventToTopicAndMarksPublished() {
    // Given: Một pending outbox event
    OutboxEvent event = new OutboxEvent("Payment", uuid,
                            "payment.succeeded", "{\"ok\":true}");
    when(repository.findTop100ByStatusOrderByCreatedAtAsc(PENDING))
        .thenReturn(List.of(event));

    // When: Publisher chạy
    publisher.publishPending();

    // Then: Event được gửi và mark là PUBLISHED
    verify(kafkaTemplate).send("payment.succeeded", ...);
    assertThat(event.getStatus()).isEqualTo(PUBLISHED);
}

@Test
void publisherMarksFailedWhenKafkaSendThrows() {
    // Given: Kafka throw exception
    when(kafkaTemplate.send(...)).thenThrow(new RuntimeException("broker unavailable"));

    // When
    publisher.publishPending();

    // Then: Event được mark là FAILED
    assertThat(event.getStatus()).isEqualTo(FAILED);
}

8.1 Complete Business Flow

🛒 ORDER CONFIRMATION FLOW (Happy Path)
1
User tạo Order
Order Service tạo order với status PENDING
2
Publish inventory.reservation-requested
OrderEventProducer gửi message đến Kafka topic
3
Inventory Service nhận và xử lý
ReservationEventConsumer nhận message, kiểm tra stock, reserve inventory
4
Publish inventory.reserved

5
Order Service cập nhật status

Payment Service xử lý payment

OutboxPublisher gửi payment.succeeded

Order Service confirm order

9
Publish order.confirmed
OrderEventProducer gửi confirmation event
10
Notification Service gửi email
OrderEventConsumer nhận event, gửi confirmation email cho user
